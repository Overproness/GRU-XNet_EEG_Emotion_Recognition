# GitHub configuration review for GRU-XNet

Reviewed **5 October 2026**. This answers the request to inspect other implementations while the first-party DEAP download is unavailable. Five public repositories were inspected at fixed commits. The review covers executable branches, example commands, and documentation; these are identified separately below. No downloaded implementation was executed and no new model was trained.

**Subsequent experiment:** after this review, the author authorized the [DEAP-only control](GRU-XNet_DEAP_Control_2026-10-05.md). That separate, independently verified run completed 28 epochs and obtained 46.25% test trial balanced accuracy. Its result does not establish that longer training or training-fitted normalization alone solves the earlier failures; the recommendations below record the original review and distinguish unrun matched comparisons.

**Main finding:** 128 Hz, four-second windows, and a learning rate of 0.001 have clear precedents. The larger differences are signal representation/normalization, electrodes, label boundaries, training duration, and whether trials or participants are held out. Repository settings provide useful development controls; they do not authenticate the mirrored DEAP recordings or establish that a particular configuration will resolve GRU-XNet's single-class predictions.

## 2. Normalization and baseline treatment differ materially

The current corrected GRU-XNet subtracts each window/channel's mean and divides by that window/channel's RMS before STFT. Consequently, multiplying a channel's entire window by a positive constant produces the same normalized input, apart from the numerical floor. Absolute channel/window amplitude is removed. This is a deliberate invariance, but it may remove useful power information. That is a hypothesis to test, not an established explanation of the collapsed runs. [Current transform](../../gruxnet/model.py).

Author TSception and EEGain calculate **one mean and standard deviation per electrode across the outer training set**, then apply those same values to held-out inputs. Relative power differences between windows survive. Both implementations perform this calculation before their inner validation split, so the statistics also contain the subsequently selected validation windows. An adaptation for GRU-XNet should split training/validation participants first, fit statistics on training participants only, and freeze them. [TSception normalization/order](https://github.com/yi-ding-cs/TSception/blob/9efd666b618d006e32e6da1d30dbc79b1d190604/code/cross_validation.py#L78-L103), [EEGain normalization/order](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/data/loader.py#L127-L177).

Baseline removal is not a single interchangeable operation:

- **TSception:** discard the first 384 samples; no baseline subtraction in the inspected loader. This agrees with the baseline-discard portion of the current GRU-XNet loader. [Loader](https://github.com/yi-ding-cs/TSception/blob/9efd666b618d006e32e6da1d30dbc79b1d190604/code/prepare_data_DEAP.py#L58-L89).
- **LibEER and DeepVANet:** average the three one-second baseline blocks into a 128-sample waveform, subtract that waveform from every stimulus second, then use stimulus data. This is not scalar mean subtraction. [LibEER loader](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/data_utils/load_data.py#L506-L543), [DeepVANet preprocessing](https://github.com/geekdanielz/DeepVANet/blob/8d395182285990cff01b73ba3623f15dd713b42d/data_preprocess.py#L324-L356).
- **TorchEEG tutorial:** construct the averaged baseline waveform, extract differential entropy from baseline and stimulus separately, then subtract the baseline **features**. This is distinct from subtracting a waveform before feature extraction. [DEAP baseline construction](https://github.com/torcheeg/torcheeg/blob/87e595ba0d97a52ad4d8e36dbd956c655b4e1993/torcheeg/datasets/module/emotion_recognition/deap.py#L213-L254), [feature transform](https://github.com/torcheeg/torcheeg/blob/87e595ba0d97a52ad4d8e36dbd956c655b4e1993/torcheeg/transforms/numpy/band.py#L119-L163), [tutorial transform order](https://github.com/torcheeg/torcheeg/blob/87e595ba0d97a52ad4d8e36dbd956c655b4e1993/examples/examples_pipeline.py#L37-L50).

The current neural representation uses 14 common named electrodes and log STFT magnitudes; these references usually use raw 28/32-electrode EEG or differential entropy. LibEER's `only_seg` route also bypasses extra filtering and feature extraction, whereas our cache applies a further 4–40 Hz filter. Copying optimizer settings alone is not a reproduction. A DEAP-only comparison also avoids prematurely conflating amplitude normalization with device/unit differences across the three datasets. [LibEER preprocessing branches](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/data_utils/preprocess.py#L19-L38).

## 3. Label policies: exact code matters

None of the inspected standard DEAP loading paths justifies the mirror's `9 - rating` modification. TSception and LibEER select the stored valence/arousal dimensions directly. DeepVANet instead joins participant rating metadata using **Participant_id + Experiment_id** during preprocessing, then names segments by the metadata's `Trial` identifier. This independently supports the ordering logic used for our spreadsheet-based recovery. It does not prove that our mirror's EEG samples or spreadsheets are first-party copies. [TSception labels](https://github.com/yi-ding-cs/TSception/blob/9efd666b618d006e32e6da1d30dbc79b1d190604/code/prepare_data_DEAP.py#L111-L132), [LibEER labels](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/data_utils/preprocess.py#L365-L408), [DeepVANet metadata join](https://github.com/geekdanielz/DeepVANet/blob/8d395182285990cff01b73ba3623f15dd713b42d/data_preprocess.py#L333-L356).

Applied to the **1,280 valence ratings in the two matching local spreadsheets**, the inspected rules produce:

| Rule | Negative trials | Positive trials | Excluded trials |
| --- | ---: | ---: | ---: |
| Current GRU-XNet: below 5 / above 5; exclude exactly 5 | 556 | 708 | 16 |
| TSception; LibEER with bounds 5,5: at most 5 / above 5 | 572 | 708 | 0 |
| TorchEEG `Binary(5)`; DeepVANet: below 5 / at least 5 | 556 | 724 | 0 |
| EEGain default LOTO: at most 4.5 / above 4.5 | 472 | 808 | 0 |
| EEGain default LOSO executable path: cast rating to integer, then threshold at 4.5 | 556 | 724 | 0 |

The EEGain LOSO/LOTO discrepancy is concrete: its subject loader casts continuous ratings to integers, while its trial loader retains the floats. At the default 4.5 threshold, a rating of 4.9 becomes negative in LOSO and positive in LOTO. That affects **84 trials** in our spreadsheets. The threshold-5 low/high conventions differ on **16 midpoint trials**. Among the 1,264 trials retained by our policy, both threshold-5 conventions agree with our recovered labels. [EEGain two loading paths](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/data/datasets.py#L519-L580), [EEGain threshold default](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/config.py#L19-L26), [TorchEEG boundary](https://github.com/torcheeg/torcheeg/blob/87e595ba0d97a52ad4d8e36dbd956c655b4e1993/torcheeg/transforms/label/binary.py#L50-L58), [DeepVANet boundary](https://github.com/geekdanielz/DeepVANet/blob/8d395182285990cff01b73ba3623f15dd713b42d/dataset.py#L86-L91).

The counts and all pairwise differences are saved in review_checks.json (local workspace evidence: `publication_runs/repository_review_2026-10-05/review_checks.json`). Keep the completed corrected runs' labels unchanged. Any conventional DEAP reproduction should declare a separate label policy and use a fresh cache/run rather than silently reinterpret an existing result.

## 4. Evaluation code that should not be copied unchanged

**TorchEEG's tutorial split is weaker than its name suggests.** `KFoldGroupbyTrial` iterates over every participant and trial and calls KFold on that trial's window rows. It therefore places windows from each original trial on both sides. For participant-independent evaluation, the library provides `KFoldCrossSubject` and `LeaveOneSubjectOut`; an independent inner validation split still needs to be constructed. [Exact split implementation](https://github.com/torcheeg/torcheeg/blob/87e595ba0d97a52ad4d8e36dbd956c655b4e1993/torcheeg/model_selection/k_fold_groupby_trial.py#L80-L111), [participant-based alternative](https://github.com/torcheeg/torcheeg/blob/87e595ba0d97a52ad4d8e36dbd956c655b4e1993/torcheeg/model_selection/k_fold_cross_subject.py#L88-L112).

**LibEER ACRNN uses validation features to fit its scaler.** Its normalization function concatenates training and validation arrays before fitting StandardScaler. Additionally, both inspected ACRNN and TSception training scripts replace an empty validation set with the test set. That fallback is not activated by the three-way DEAP preset above, but it must be replaced before using a preset without validation. Otherwise test data influence checkpoint selection; in the ACRNN route they also enter normalization. These findings concern these code paths, not every experiment in the library. [Normalization](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/data_utils/preprocess.py#L427-L456), [ACRNN fallback](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/ACRNN_train.py#L99-L107), [TSception fallback](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/TSception_train.py#L107-L113).

**EEGain's inner validation does not match its documentation's participant split.** The inspected LOSO loader holds out the test participant correctly, then selects class-wise random window indices for validation. Fit normalization after a genuinely independent validation-participant split when adapting it. [LOSO order](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/data/loader.py#L157-L181), [inner window indices](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/data/loader.py#L229-L279).

**Follow-up EEGNet implementation check:** the pinned EEGain EEGNet creates its classifier inside the first forward pass. Its ordinary CLI constructs the model and optimizer before that pass, leaving the subsequently added classifier parameters outside the optimizer unless an extra initialization step is supplied. It also returns softmax probabilities to a cross-entropy loss intended for logits. These are findings about this pinned code route, not proof about the implementation used for any published result. The separate DEAP control registers its classifier before optimizer construction, returns logits, and tests that the classifier receives gradients and updates. [Dynamic classifier](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/models/eegnet.py#L125-L143), [CLI construction order](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/run_cli.py#L197-L211), [optimizer/loss](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/helpers.py#L420-L425).

**DeepVANet's pooled mode does not imply unseen participants.** `DEAPAll` builds participant/trial/segment tuples, then partitions positions in the supplied index list. Actual independence depends on the caller's index construction; the class itself does not reserve participant IDs. Its default multimodal data cover participants with face recordings, rather than all 32 DEAP participants. [Dataset indexing](https://github.com/geekdanielz/DeepVANet/blob/8d395182285990cff01b73ba3623f15dd713b42d/dataset.py#L184-L232).

Two further configuration details matter for reuse. LibEER TSception derives temporal kernel lengths from `num_datapoints`, whereas the author implementation uses the sampling rate; changing the LibEER input from one to four seconds also changes its temporal kernels. EEGain's SEED-IV loader hardcodes 1,000 Hz and session 1; applying that path to our 200 Hz, three-session files requires a corrected adapter. [LibEER kernels](https://github.com/XJTU-EEG/LibEER/blob/dddff9776dbdae21195fe320dff0a5ba61628a18/LibEER/models/TSception.py#L29-L46), [author kernels](https://github.com/yi-ding-cs/TSception/blob/9efd666b618d006e32e6da1d30dbc79b1d190604/code/networks.py#L14-L23), [EEGain sampling assumption](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/data/datasets.py#L125-L136), [session assumption](https://github.com/EmotionLab/EEGain/blob/d6892f5586181f345969651a9baedabd828bb1c5/eegain/data/datasets.py#L184-L196).

## 5. Recommended next development experiments

These are recommendations, **not completed experiments**. Make choices on training/validation data and keep the previously inspected test scores out of configuration selection.

1. **Establish a DEAP-only control.** Use the recovered labels, 128 Hz, 4-second non-overlapping windows, and a compact raw-EEG EEGNet or author-style TSception. Compare it under exactly the same participant-independent protocol and metric as GRU-XNet. A 32-electrode EEGNet control and 14-electrode version can separate montage loss from representation/model effects; TSception needs its documented 28-electrode ordering for an author-style reproduction.
2. **Compare amplitude normalization directly.** Keep GRU-XNet's architecture fixed and compare per-window RMS normalization against training-fitted per-electrode scaling or training-fitted log-power scaling. Start within DEAP. Save fitted statistics and use them unchanged for validation/test. Our existing amplitude-preserving bandpower control is also near chance, so amplitude preservation alone is not yet supported as a solution.
3. **Allow a meaningful optimization period.** Your full neural run stopped after six epochs with an epoch-1, single-class checkpoint; the references budget 50–1,000 epochs. A predeclared maximum of 100 epochs with patience 15, an initial period before stopping, and a validation-loss tie-break when balanced accuracy is unchanged is a reasonable development candidate. Record loss, probability spread, per-class predictions, and gradients. Longer training is a hypothesis, not a guarantee. These recommendations require training-code changes; they are not a command already supported in full by the current CLI.
4. **Compare regularization in a small controlled study.** Initially disable augmentation to match the basic raw-EEG controls, then restore it as an ablation. Test learning rates 0.001 and 0.0003 on validation only, and compare the current AdamW/cosine setup against a fixed-rate Adam control. Keep effective batch size around 32–64. On the 6 GB RTX 3050, use a measured microbatch of 16 with accumulation as needed; verify each model's memory usage before increasing it. Accumulation does not exactly reproduce a batch-64 run with BatchNorm.
5. **Return to the pooled/cross-dataset question after the single-dataset control learns.** Preserve the named electrode mapping, original trial identities, independent validation subjects, and training-only augmentation. Declare how per-dataset units and missing baselines are handled. Binary SEED-IV valence derived from emotion categories is a different task from its usual four-class benchmark, so published four-class scores cannot be used as matched binary references.

ACRNN is the closest additional family-level baseline in this review: channel attention + CNN + recurrent network + self-attention. It is a useful comparator after correcting its validation handling. TSception and EEGNet provide simpler controls that help determine whether the problem lies in the data/representation or in the more complicated GRU-XNet training setup.
